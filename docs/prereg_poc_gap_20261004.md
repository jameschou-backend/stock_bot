## 委託與資料問題

買單或賣單在既定執行階段遇到 `ReplayDataUnavailable`（缺資料、來源價量衝突、交易資料不可用等），該日該筆委託整筆視為未成交。普通盤和盤後零股是一筆預定委託的兩通路；任一必要通路資料異常，兩者均零成交、零費用。若另一通路已在程式內暫時記帳，必須完全回復本筆委託造成的現金、股數、費用、成交列及容量變化。不得借用日線中點、補造逐筆、假裝停牌或把未知寫成官方零量。

- **買單**：不建倉，保留原盤前計畫、當日預算與嘗試名額鎖，不因事後看到資料有問題補買下一檔。下一交易日照原候選及資源规则處理。
- **賣單**：保留持股、成本、原出場理由與觸發日期；下一交易日沿原退出迴圈繼續嘗試。未賣出的股票持續按原估值規則反映損益，不能刪除持股或產生虛構賣款。若期末仍未出清，明列未出清部位。
- **POC 必要資料未知**：原策略已有的非可恢復資料品質問題、整日恢復原排序機制保留。其他原會中止的未知 POC 候選明確排除，再以未改動的原盤前資源狀態重排其餘候選；不把未知寫成 POC 上移或未上移。每一排除附事件、訊號日期與原因，重用查詢結果，不重複抓資料。
- 程式錯誤、來源 hash 被修改、現金或股數不平、未解決公司行動等不能假作正常的未成交；須修程式或保存未完成帳本。此規則只處理有明確記錄的資料異常，不能吞掉任意例外。

盤前計畫階段若缺漲跌限價或前價，不能補造可成交計畫；需明確記錄不可下單並保留同等資源限制。未有可核對估值或公司行動時不得宣稱完整 NAV。
