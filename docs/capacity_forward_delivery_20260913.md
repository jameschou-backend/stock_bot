## 委託與模擬成交的精確邊界

- 新買單只能在下一交易日開盤前建立；不以當日尾盤訊號假定更早成交，不用隔日成交量決定事前排序。
- 買單限價固定為訊號日原始收盤價；不盤中追價、不將未成交買單自動帶到隔日。已有賣出決策不因價格反彈或新訊號缺漏撤銷。
- 保留原前向引擎的12%收盤停損與63交易日期限。這是訊號與後續委託，並非保證以12%損失成交。
- 模擬需兩次15至90秒間隔的已取得觀察，報價各不超過15秒舊；深度及區間增量各限10%，另加入0.1%不利滑價、交易單位及費稅，超出限價仍未成交。未觀察區間不補填。
- 相同行情提供給三帳本，但容量為獨立假設，不把三份比較帳戶當作在市場同時下單的合併容量。
- 整戶20%門檻依已核對的收盤NAV，不是即時盤中止損；回撤觸發後，即使恢復也不自動解除。這個風險覆蓋同時作用於排序與現金對照，0050維持獨立買入持有基準。
- CSV對帳僅比對提供的回報，未提供不代表沒成交，檔案也不能自動證明券商來源。限價異常需核對，不將它靜默裁切成合法成交。

## 畫面與執行

工作台「策略研究」優先顯示「實戰前準備：成交金額排序的每日模擬」。可查看三帳本資產、候選排序、未入選原因、限價與已成交股數；可更新來源、暫停新增、保存公司行動核對及上傳已對應欄位的成交CSV。舊版前向帳本移至選擇展開的區塊，原始資料未修改。

手動查看（不聯網、不改帳）：

```sh
python scripts/run_capacity_forward.py status
```

更新來源（一批最多12次，重用共享快取）：

```sh
python scripts/run_capacity_forward.py refresh
```

執行一次有界流程，依交易日與時間自行選擇階段：

```sh
REQUESTS_CA_BUNDLE="$PWD/.cache/capacity-tls-20260913/bundle.pem" python scripts/run_capacity_forward.py run
```

TPEx中繼憑證已使用既有certifi根憑證驗證憑證鏈與主機名，再建立本程序專用bundle；沒有關閉TLS、變更系統信任或.env。憑證／指紋異常應停止並重新核實，不能繞過。新的官方還原價輸入仍可能遇到供應商傳輸失敗，需保留阻擋後重試，不把缺資料當沒事件。

真實回報比對（不送單、不入模擬帳）：

```sh
python scripts/review_capacity_executions.py --csv /absolute/path/executions.csv --role strategy --output /absolute/path/execution-review.json
```

CSV欄位：`execution_id,order_id,stock_id,side,channel,qty,price,fee,tax,executed_at`；side為buy/sell，channel為board/odd，qty單位為股，executed_at須含時區。order_id需對應已存在的事前計畫；輸出路徑拒絕覆寫。券商檔案需先對應欄位，不能猜測張／股或稅費單位。
