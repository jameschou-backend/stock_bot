# 原公司母集合漏列的本機歷史行情

以既有上市／上櫃歷史身分盤點對照原 1,974 檔公司母集合，找到 **49 檔研究期間曾有市場身分、卻沒有納入原封存行情的股票**。盤點時包含尚待證明普通股類別的候選，因此這份原始行情補包本身不授予投資資格；後續必須套用新版官方身分證據。

這 49 檔的行情實際上已存在本機 MySQL，不必重新耗用 FinMind。已透過唯讀 SELECT 封存至 `.cache/historical-cohort-supplement-20260925/verified-snapshot/`：

| 範圍 | 列數 |
|---|---:|
| 2021 年預備資料 | 11,556 |
| 2022-01-03 至 2026-09-09 | 24,108 |
| 合計 | 35,664 |

資料按 `stock_id/date` 唯一，成交量使用資料庫的**股數**，未乘以 1,000；沒有改寫原公司名冊、行情矩陣、訊號或帳本。也沒有把行情最後出現日猜成下市日，或把缺日期填成零成交。

其中 **641 列隔離，不能直接投入特徵或估值**：555 列有記錄量但 OHLC 不完整、86 列開收盤超出高低價範圍。前一種可能涉及普通盤價格不可得而其他交易通道仍有量，不能僅憑此斷言來源造錯。原始值完整保留，隔離原因逐列記錄，沒有捏補價格。

這次消除的是「本機已有資料卻沒封存進研究材料」的缺口。仍需把完整歷史母集合、停復牌與公司行動放進**新的**訊號和帳本版本，重新檢查候選名單、資金及報酬；不能直接沿用原 20 案的結果。原先存活者偏差並未因多了一個行情檔而自動消失。

重播：`python scripts/prepare_historical_cohort_supplement.py`。此預設命令只讀封存檔，會檢查舊名冊／行情來源、補包指紋、日期、數量與隔離結果，不連 DB 或外部資料服務。只有明確加 `--prepare` 才會做本機 SELECT，並要求全新的輸出目錄。

驗證：9 項測試通過；獨立覆核將 DB 與 HTTP 呼叫設為立即失敗後，正式補包仍可成功重播。沒有新 FinMind 查詢或 DB 寫入；沒有重算報酬，也沒有提升實盤資格。
