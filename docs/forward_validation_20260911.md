## 前向紀錄如何運作

工作台「策略驗證」新增資料／訊號封存、報價擷取、預定委託、取消及紙上成交回報匯入。CLI：

```sh
python scripts/forward_validation.py prepare
python scripts/forward_validation.py freeze
python scripts/forward_validation.py plan
python scripts/forward_validation.py quotes --stocks 0050 1560
python scripts/forward_validation.py status
```

1. 延伸原本封存的價量／固定公司名冊，以相同 `build_signals` 及族群領先、0050趨勢條件計算當月訊號。新公司行動來源含上市上櫃六種公告，新FinMind還原价從共同錨點銜接。保留原始檔、程式與來源雜湊；不改旧帳本。從9/9基準向後最多10個交易日，超出會明確要求回補，避免不受控的下載。
2. 只接受當日收盤資料、當日生成並在未來進場日前封存的原策略訊號。週末／非交易日、18:00以前、缺市場、舊訊號或來源異動會拒絕當成有效前向訊號。未來交易日僅使用官方日曆，新增空白價格列，不填未來價格。
3. SQLite交易鎖、事件序號及hash鏈保留順序。已封存規則與同日訊號不可覆寫；不同程式版本須另開紀錄，不能拼成同一份前向成績。hash鏈只能偵測一般修改，不能防止管理員重建整份資料庫。
4. 初始委託試驗按100萬元、三個個股名額計預算，使用訊號日原始收盤作限價，開市前留存、不盤中改價；整張受前20日均量1%限制，零股分開計最低手續費。**這個固定前收限價是新的前向成交試驗口徑，並不等同歷史收盤價＋滑價回測。** 不把沒買到的資金虛構成有買到，也不追補買單。
5. 報價以Sponsor即時快照一次取全市場後篩選，10秒快取、0次自動重試、共用用量帳本。文件只標示「成交時間」且未明列量單位／零股深度，原樣記錄來源單位，**不把它換成零股可成交股數**。舊成交時間標記stale；不拿收盤後快照補成早上的成交。
6. 紙上成交回報需對應事前委託、有效執行日、數量、限價、費稅及唯一report ID；測試覆蓋部分成交、重複回報、超量及透支拒絕。回報是使用者提供，未接券商認證；FinMind報價本身不能作成交回報。真實帳本完全分開。
