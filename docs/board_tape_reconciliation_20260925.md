本輪核對目前 20 組封存資金帳戶實際需要的 917 個普通盤股日。官方日總量對帳補強的是股數、成交金額與 OHLC 的獨立核對，尚不證明逐筆時序完整、排隊順位或自己的委託一定成交。

TPEX 42 個衝突中，5 個股數與金額皆不一致，37 個只有金額不一致；42 個 OHLC 均一致。所有差額都保留，不加容忍帶來提升通過率。

## 對帳口徑

- FinMind `TaiwanStockPriceTick` 上市/上櫃的 `volume` 是張，精確乘 1,000 轉股；價格用整數分計算金額，避免浮點誤差。
- 普通盤只納入 `09:00 <= time < 13:34` 的正成交量列，保留 13:33 延後收盤。14:30 定價列獨立統計，不算普通盤；其他正量時間明列異常。零量列不影響 OHLC。
- TPEX 直接用官方「上櫃股票每日收盤行情（不含定價）」同日同股票的股數、金額、OHLC。官方成交筆數保留，但不與供應商行情訊息列數硬比。
- TWSE `MI_INDEX` 明寫含一般、零股、盤後定價、鉅額。依日表扣除 `TWTC7U` 盤中零股、`TWT53U` 盤後零股、`BFT41U(selectType=ALL)` 定價、`BFIAUU(S)` 單股鉅額，以及 `BFIAUU(M)` 股票組合。定價成交數量是千股，兩種零股必須是 `type=ALL`，缺任何分項不能當零。
- 原型 2022-01-04 的股票組合鉅額表是空表；未實作非空組合明細時一律阻擋，不推定組合沒有買該股。
- 原型先取 TWSE 1560/2340/2615 與 TPEX 3508/6284/8069；同一 TWSE 分項表也涵蓋必要股票 4755/8374，5 個均一致，沒有另抓。

原有 `skills/intraday_limit_replay.py::match_ticks` 已限制 `09:01 < time < 13:25`，所以此處發現 14:30 資料存在，**不是說舊成交模型把盤後量算入可買量**。此次不更改已封存行情、訊號、交易或報酬。

## 衝突診斷與隔離

5 個缺量股日的 raw 本身已比官方股數少，raw 列數與 normalized 列數相同、沒有刪重複、沒有時段外列或 14:30 列可解釋差額。37 個金額差異也保留；可能涉及供應商訊息/成交價格語意或原始資料差異，現有證據尚不能確定原因，也不能虛構缺失成交的時間或價格。

正式 JSON 的 `quarantine` 列表包含日期、股票、原始 SHA-256、差額與診斷。新研究可先呼叫 `assert_not_quarantined(report, day, stock_id)`：遇缺來源或衝突即拒絕；通過此負面檢查仍不代表已具逐筆成交資格。

新增 `load_reconciled_tape(report_path, root, day, stock_id)` 作為後續研究的讀取入口：先驗報告與完整 source/code hash，再套負面檢查與原始 parquet hash，最後只回普通盤資料及 `research_only_daily_aggregate_checked`，strict、sequence complete、own fill、live 均為 false。**此入口尚未接管舊封存引擎**，因此不能稱舊績效已自動套用新隔離；原績效保留原始假設，介面另揭露此衝突證據。

## 成本與重現

實際準備使用 193 次公開官方 HTTP（10 次 endpoint/分類/文件原型探查，183 次 TPEX 日期批次），0 次 FinMind、0 付費購買、0 DB 或排程變更。原型中 TPEX 2022-01-04 與全批次有一次重複讀取，已計入總數。批次每次間隔 1.5 秒、不自動重試；先記錄用量，再送請求，重跑不會重抓已消耗的 identity。

```bash
python scripts/audit_board_tape_reconciliation.py
python scripts/audit_board_tape_reconciliation.py --verify
python -m pytest -q tests/test_board_tape_reconciliation.py
```

輸出 `artifacts/forward_simulation/board_tape_reconciliation_20260925.json` 與 `.sha256`。`skills.board_tape_reconciliation.verify_report(path, root)` 檢查報告 SHA、來源與程式碼的完整 hash closure。離線重播 0 HTTP；正式 report 不含執行時間等不可重播欄位。測試 31 項涵蓋日期/欄位/單位、部分表不可推零、盤後與延後收盤、缺來源、負殘值、股數/金額衝突、隔離與 hash 竄改。

## 未完成 TWSE 批次的精確計畫

TWSE 所需 407 日期，已具一日完整分項，還有 406 日期。逐日方案最低另需 `406 × 5 = 2,030` 次（總表、盤後零股、定價、單股鉅額、組合鉅額），盤中零股已有 397 日期快取，尚缺 10 日期，所以最低 2,040 次。若某日有股票組合鉅額，還要額外抓組合成分明細，數量未明。

為避免本輪多開約一小時的批次，未啟動此大批次。後續應先盤點其他快取、尋找有證據且同口徑的普通盤日表來源，再依 immutable request plan 抓真正缺失的分項；不能改拿全市場量宣稱對帳。
