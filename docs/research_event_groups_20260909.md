# 營運事件與題材群：資料稽核及診斷結果

這輪完成自動新聞線索、歷史題材成員、持有及退出引擎，並執行固定 30 組診斷。**未取得可用來判定策略優劣的證據，也沒有通過實盤資格。** 原文抽查發現供應商日期錯置；歷史數字即使很好看也不能證明能獲利。

## 已確認的資料問題

- 華東 8110 的「Q2 轉盈」新聞：DB 與本次直接重查 FinMind 都給 2022-01-01 18:14:13，原文卻明確是 2020-08-14、2020 第二季的報導。原本 ingest 僅將供應商 date 轉 datetime，未自行改日。
- 每類事件按時間取最早三篇、共 12 篇，不看後續報酬。1 篇明確錯置、2 篇日曆日期不同仍需核對時區、1 篇僅確認同日、8 篇原文未取得。不可將抽樣比例當全體錯誤率。
- 標題規則仍會誤收「轉盈契機」等展望或行情解說。不能只刪幾個已知錯例，就把整份資料當乾淨。
- DB 2021-07-01～2025-11-30 共 2,867,358 列；16 個整日缺口各查一次，FinMind 全回空，覆蓋仍未知。
- 供應商歷史新聞是在 2026 年回補，缺原始首次發佈版本。現在的公司名稱與公司名冊仍有存活者偏差。

## 本輪基準重建錯誤及修正

第一輪診斷發現，本次重建官方還原價時漏掉 0050 的 ETF 單位分割，導致錯誤的負基準報酬。六種股票公司行動來源沒有涵蓋此 ETF 分割。初始報告全部作廢，保存在本機 invalid-before-benchmark-split-fix 目錄，不供 UI 顯示。

依[證交所公告](https://www.twse.com.tw/staticFiles/news/news/tsecnews/8a8216d696b406fc0196ce27c2e90063.pdf)及[元大公告](https://api.yuantafunds.com/ECImage/ECBackstage/file/2025-06-17/ca6610a73d444bc09bc2035df79bfd25.pdf)，補入 2025-06-18 一單位換四單位的明確事件，加入跨停牌期間測試，然後重跑全部固定條件。沒有更動選股門檻。此修正只作用於研究快照。

修正後，0050 兩種口徑在相鄰有報價日的最大報酬差異為 0.530 bp。全體股票仍有 210 個可比較日報酬差異超過 50 bp；556 筆公司行動疑涉現金增資。不能因此宣稱全市場還原價或股息現金帳已正確。

## 固定規則及診斷數字

事件限報價、訂單／客戶認證、量產／出貨成長、獲利改善。題材群成員只由訊號日前 180 日新聞明確提及的公司建立；包含正負消息，不倒填目前 FinMind 產業鏈分類。群體確認排除候選股自身，至少三個有效同群、覆蓋至少 80%，檢查相對 0050 報酬、站上均線比例及成交比重。成交額為收盤乘股數估值，不等於資金淨流入。

題材群從資料不足首次轉為通過也可能產生訊號，因此訊號增加不一定代表實際資金突然轉向。三組都須通過個股流動性與趨勢要求，最多十檔，入場預算每股不超過前日 NAV 10%。持有上限 63／126 交易日，15% 進場停損／20% 高點回落後次日執行；擋住賣單逐日重試，不保證虧損止於門檻。

## 效能與重現

訊號準備 28.553 秒；全部 30 組診斷 5.110 秒。快取重算零 FinMind 請求；本輪收集共 18 次（缺口 16、原始 API 核對 2），另有限量 12 個原文 URL 查詢及網頁核對。沒有重新訓練模型。

資料首次整理與快取重算分開計時：早期 SQL 月內文字篩選實測約 7 秒，改成日期索引取月資料、Pandas 篩選後約 0.64 秒；2021-07 篩出的識別集合相同。首次匯出曾中斷後續跑，manifest 的 24.404 秒是續跑時間，不能稱為完整首次建庫耗時。單筆事件端點改用 NumPy 陣列，不再每事件切整個寬表。

```sh
make prepare-event-groups     # 準備／驗證快照；只補尚未快取的缺日
make diagnose-event-groups    # 明示診斷用途，無 DB 寫入、無網路抓取
```

直接執行研究腳本而未加 --diagnostic-only 會停止。報告、訊號、程式、事前規格與來源稽核保存 SHA256；缺依據或雜湊變動，UI 不顯示舊數字。CLI 每次重算還會核對大資料快照，UI 只讀小摘要與雜湊，開頁不會跑回測。

## 接下來的研究順序

1. 先建立可信的事件時序：供應商日期、原文發佈／更新、首次抓取各自保存，以原文識別去重；舊聞、日期衝突及無法查證者隔離。從實際封存日累積向前追蹤，不能回填成過去已知。
2. 逐股核對分割、減資、現金增資與股息，補完整歷史上市下市名冊。已知缺陷未解決前維持研究用途。
3. 以日期可信的營收／財報公告檢查營運改善，再用已封存新聞解釋題材。之後才比較事件策略、同曝險的 0050，以及 0050 核心加事件部位。另開事前規格，不拿本輪最好數字調參。
