# 不使用模型的選股方向研究

2026-09-09。本輪完成三個固定規則、兩種成本情境的探索，**尚未找到足以取代 0050 的方法**。後續值得先查的是「接近一年新高＋公告後營運成長確認」；後半部尚未回測，是待驗假說，不能宣稱勝過模型或 ETF。

## 判斷

- 單純中期動能及波動調整動能在 2023–2025 年未贏過 0050；沒有證據支持直接採用。波動調整後的排序也沒有換來较小的歷史最大回撤。
- 接近一年新高是三個規則中表現較好的方向，但仍未通過事前的兩段比較門檻；2026 年短期好看，不能抵銷前段落後及超過 60% 的歷史跌幅。
- 先暫緩擴充模型及參數搜尋。下一輪先修正歷史股票身分與候選涉及的還原事件，再固定「新高趨勢是否需要營收確認」這個單一問題。營收必須按實際公告可用日加入，不能把月初 period date 當公告日。現有公告歷史不足，不能補造十年資料。
- 完成資料查證後，原三個規則可原封不動重驗；營收新假說另留事前紀錄。最後需要往後累積紙上結果，而非重新切分已看過的歷史，再稱全新樣本外。

## 追查與資料修復

1. 首輪發現 0050 原始行情只從 2026-02-04 開始，基準被錯當現金。該輪作廢，補 0050 十年原始價，一次請求；新增基準無法在共同起始日買入即失敗的檢查。
2. 修正舊持股無法賣出時仍買到超過十檔的模擬缺陷；規則參數不變。
3. 第二輪發現 2026-05-21、05-22 整日原始行情缺漏，造成六月全體規則錯誤空手。補兩天全市場，共兩次請求；增加每日原始行情覆蓋不足 90% 就停止的檢查。最終原始行情相對還原價每日覆蓋最低 99.09%，缺原始價剩 30 列；這只證明交集覆蓋，不證明整個市場十年齊全。
4. 股票主檔有 2,149 筆本輪類型／市場候選缺上市日期；171 筆目前已非掛牌狀態未被直接刪掉，但仍不足以排除存活者偏差或當時市場身分錯置。
5. 後驗檢查持倉遇到單日還原價變動超過 50% 的事件，新高規則曾持有 3592 於 2021-02-17 上漲約 60.7% 的資料點。這類點需要確認當時市場身分及價格，不用上市股票漲跌幅假設直接當正常交易。
6. 對新高壓力情境，按逐筆買賣現金流扣成本加總、已結清股票歸因，7610、9103、5314 分別貢獻初始資產約 +59.94、+35.05、+30.30 個百分點，合計約占全期淨利 51.1%。其中 9103 是主檔分類成 stock 的存託憑證，5314 位於既有還原因子截斷查核清單。不能看到其獲利再挑選保留，或把刪除它們後的數字當新驗證；先核對資料。

選股條件、日期及成本維持 [事前登記](prereg_rules_20260909.md)，所有資料／模擬缺陷修正有追加紀錄。比較讀到 4,632,956 列、2,080 個代號（含 0050）；相同歷史已用於先前研究，不是全新測試集。完整報告保存輸入、主檔、程式及事前登記 SHA-256。

## 使用方式及效率

在工作台「策略驗證」上方看三種規則與 0050 比較，切換基本／較高滑價，展開規則說明或下載摘要。它讀已完成報告，不會每次開頁面抓資料、重新訓練或選股。

```sh
# 已有本機還原價與原始價快照時，僅補三個已確認缺口。
# 共最多三次初始查詢，重試另計；已完成檔案跳過，共享 FinMind 額度。
python scripts/research_rules.py --prepare-inputs

# 六個比較臂＋0050，讀本機資料，零 API request。
make research-rules
```

本次六臂計算約 **4.10 秒**，其中讀取及校驗約 3.09 秒；不含另行啟動 Python／寫報告的全部牆鐘時間。本輪資料修復實際 **3 次 FinMind request**。驗收 pipeline 的日常更新另計。有限次數比較取代參數網格搜尋；沒有模型訓練。頁面與 MCP 的 `get_strategy_evidence` 共用精簡報告。

前置依賴沿用專案 requirements、MySQL 主檔及原有 `artifacts/adj_prices/adj_prices_10y.parquet`、`artifacts/cache/prices.parquet`。缺少大快照時明確報錯，不自動回補全市場十年；準備命令只修補已記錄的三份小資料。完整結果在 `.cache/rule-research/report.json`，未通過資料驗收的兩輪另存 `.cache/rule-research/report.invalid-benchmark.json` 及 `report.incomplete-raw.json`。
