# 回測前先準備資料

此入口延續 `holder_flow_20260927` 已封存的六組個股訊號，搭配一般／合併壓力情境與兩組獨立 0050 基準，共 14 個帳戶。不修改選股、排序、成本、停損、持有期或資金配置。

## 使用方式

```bash
# 先合併本機已驗證來源、輸出缺漏清單；完全不抓新資料
python scripts/prepare_holder_flow_accounts.py --prepare

# 依固定帳戶的交易路徑補資料；不發布這個線上準備階段的報酬
make prepare-holder-flow

# 確認全部 14 個路徑完成，並核對訊號、引擎與資料版本
make check-holder-flow

# 只有預檢通過才會開始正式離線帳戶回測
make backtest-holder-flow OUTPUT=.cache/holder-flow-account-replay-a
make backtest-holder-flow OUTPUT=.cache/holder-flow-account-replay-b
python scripts/prepare_holder_flow_accounts.py --compare \
  .cache/holder-flow-account-replay-a .cache/holder-flow-account-replay-b
```

預設資料準備目錄為 `.cache/holder-flow-prepared-20260928`；`--cache` 可指定另一個新版本。不修改原始研究的封存資料與結果，也不刪除舊版失敗證據。

## 如何判斷是否能正常回測

- `inventory.json`：整個候選集合缺哪些股票的漲跌停、股利檔案，以及各市場已有的零股日期。**檔案存在不等於每一天完整，也不等於公司行動條款完整。**
- `reuse.json`：每份重用來源的出處與雜湊、內容衝突與不相容來源。原始檔、正規化檔、兩者連結與現行解析器均核對；衝突不自動選邊。
- `budget.json`：每次資料請求先記帳，失敗保留，不因換策略或重跑而重複嘗試同一個失敗請求。FinMind 仍經專案共用 5,400／小時額度帳本；本次準備上限 2,000 次 FinMind、600 次官方零股查詢，並非必須用完。
- `progress.json`：逐個帳戶的準備進度與首個無法通過的原因，不含報酬。
- `preparation.json`：所有固定帳戶的準備結果及資料、訊號、引擎指紋。
- `preflight.json`：任何帳戶未完成、案例集合不同或指紋改變，`ready=false`；正式入口拒絕開始績效回測。
- `reproducibility.json`：兩次完整離線回測的 14 份帳戶結果逐檔一致才產生通過紀錄。

準備過程可沿固定策略走訪交易路徑以找出實際依賴，遇到不能補的來源或公司行動會保留原因，再檢查其他帳戶。這不是用缺資料來排除股票，也不是拿準備過程的損益挑選策略。未走到的候選股票仍列在資料清單中，不能宣稱其所有歷史皆已補齊。

**`ready=true` 的範圍是指定資料版本、固定策略與 14 個情境可以完成日資料帳務模型。** 改變策略、回測期間、名額、出場或資料時，都需要重新準備與驗證。日量與最後報價不能證明委託當時一定成交；這個關卡不會將 `live_qualified` 改為 true，也不消除歷史名冊、首次公告版本或反覆研究同一期間的限制。

## 來源受阻

沿用 `.cache/official-origin-holds/` 的停止紀錄；遇到官方安全驗證不反覆打同一網址。缺資料不以昨收乘上 1.1／0.9 推算、不用普通盤成交量代替零股，也不跳過未核實的配股或付款日期。FinMind 額度錯誤會保留進度並中止，依來源回覆的恢復時間处理。

FinMind 官方資料文件：[每日漲跌停價](https://finmind.github.io/tutor/TaiwanMarket/Technical/)。資料集的存在不代表本機已下載，或每檔每個歷史日期皆已通過驗證。
