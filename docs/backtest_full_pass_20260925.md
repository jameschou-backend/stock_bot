## 效能、配額與可重現性

- 原始成功快取重用，失敗有明確原因；不把空回應當作零成交。FinMind 衝突重查只用 42 次，經既有共享配額控制；行情補包不重新下載。
- TWSE 本輪 ledger 為 398 次 transport 呼叫，舊 fetcher 未記錄 redirect hops，不能把它當精確 wire HTTP 次數。新 fetcher 禁止自動 redirect，拒絕即停止，先寫 receipt 再斷路，續跑不清零預算。
- 七份核對報告、父報告、原始來源、範圍及程式指紋互相綁定。畫面來源核對失敗時不顯示舊數字；不會退回過期報告冒充最新結果。
- 介面首次讀取仍完整驗證，本機實測 42.481 秒；來源未變時重用成功結果為 0.887 秒。快取逐次核對 10,705 個檔案系統指紋，包含檔案變更時間、身分、大小與 sidecar；修改內容後還原修改時間仍會失效。獨立記錄七個驗證器實際讀取的 6,175 個專案檔案，確認全在守門範圍內。這是本機實測，並非整頁所有舊研究區塊的載入時間承諾。
- CLI／發布的 `load()` 每次完整驗證；只有畫面使用成功快取。首次驗證前後變動、缺檔或失敗都不建立快取；回傳複本、重用前後重新檢查來源，並行 session 共用同一個驗證過程。
- 原報告、帳本、模型、`.env` 及排程設定未被改寫；本輪沒有下單。必要 pipeline 驗收會更新本機衍生資料，不會取代封存研究輸入。
