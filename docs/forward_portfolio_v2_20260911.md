# 前向驗證資產帳本 v2（2026-09-11）

## 結論及證據邊界

這次補的是可以對帳的紙上持倉、資金與出場流程，沒有重新最佳化選股，也沒有新增可宣稱的策略報酬。策略仍 `live_qualified=false`。v2 與舊歷史回測不同：12%停損採收盤確認、下一交易日限價；不把歷史 +710.81% 套到本版。

舊 `.cache/forward-validation/journal.sqlite3`、程式規則和4筆原始事件保留。新版使用 `.cache/forward-validation/portfolio-v2.sqlite3`，100萬元獨立期初資金，不複製舊版預定委託或成交。SQLite交易序列化寫入、事件雜湊串與唯一回報編號防止重複或變造。程式或規則改變後拒絕繼續寫入，需另開版本；雜湊不是外部時間戳認證，成交仍是使用者提供的紙上回報。

## 已實作

| 項目 | 行為 |
|---|---|
| 複利 | 個股上限為最後完整收盤淨值的1/3；最多3個持股或預留名額，不用固定100萬元重置 |
| 費稅 | 按回報費稅入帳；買入費用計入成本，部分賣出按平均成本分攤。預留估計手續費0.1425%、最低20元；不再額外重複扣模擬滑價 |
| 部分成交 | 只減少已成交股數與現金，餘額仍預留；取消只釋放未成交部分；重複回報不重複入帳 |
| 過期委託 | 顯示到期待核對；當日結算及新單必須先核對舊單。遲到、倒序或已結算日回報拒絕自動回填 |
| 流動性 | 個股需20日完整流動性、均成交金額至少5000萬元；整張委託合計不超過20日均量1%。零股1至999股，但不能以此證明有成交深度 |
| 0050 | 個股優先、餘款提出0050計畫。資金不足先封存個股資金需求並提出0050賣出；只在確認賣出後才允許釋放買單，沒有墊款 |
| 出場 | 收盤達調整後進場價88%或持有63個已知交易日，下一交易日提出收盤參考限價賣單；剩餘出場決策保留，反彈不取消。限價可能賣不掉 |
| 股息 | 除息日確認前日持股資格、調整停損基準、列應收；到實際交付日確認股款後才增可用現金 |
| 分割 | 調整停損基準，待確認整數股數交付才更新可交易股數；未交付期間停止交易與完整NAV |
| 資產 | 使用明確日期完整收盤價。缺價、公司行動未核對、待交付分割股不顯示完整NAV；不拿成本價補損益 |
| 效能 | 持倉帳本不跑模型、不跑歷史回測、不打FinMind。收盤只查DB當日持股及0050價格和交易日曆；原即時報價共用限額與10秒快取 |

紙上資金政策為確認賣出後可供買入的交易額度，不等於銀行已完成T+2交割。個股不加碼舊部位、不重試過期買單。零股只接受盤中9:10至13:30成交回報，整張為9:00至13:30；暫緩收盤、盤後零股不在本版支援範圍。交易日曆以DB封存資料為準，不用週一至週五推測。

## 使用

研究頁上方現為新版帳本：

1. 先在「原策略訊號封存與舊版證據」保留當日原策略訊號（仍須先執行原訊號資料準備）。
2. 登錄當日成交；核對未成交的剩餘委託後取消。持股公司行動若有發生，先登錄權益或交付，再勾選已核對。
3. 18點後「封存今日收盤資產」，再按「建立下一交易日紙上計畫」。重複操作不重複建立同一單。
4. 下一交易日有可信紙上成交回報才登錄實際股數、價格、費稅、時間及唯一編號；未成交不記獲利。
5. 0050賣出完成且已入帳後，按「釋放今日資金需求」。只能使用盤前封存股數及限價，不能事後挑更好的股票。

CLI（均不下券商單）：

```sh
python scripts/portfolio_forward.py status
python scripts/portfolio_forward.py close
python scripts/portfolio_forward.py close --actions-reviewed
python scripts/portfolio_forward.py plan
python scripts/portfolio_forward.py record --report /absolute/path/report.json
python scripts/portfolio_forward.py release
python scripts/portfolio_forward.py export
```

成交JSON示例（測試資料，禁止當實際成交匯入）：

```json
{"kind":"fill","id":"example-report-1","order_id":"existing-order-id","qty":100,"price":"99","fee":"20","tax":"0","executed_at":"2026-09-14T10:00:00+08:00","evidence":{"source":"paper_execution_report","report_id":"example-report-1"}}
```

公司行動需使用可核對官方事件編號和來源。現金權益JSON格式（示意，不是實際事件）：

```json
{"kind":"entitlement","id":"official-event-id","action_id":"official-event-id","action_type":"cash","stock_id":"2492","ex_date":"2026-09-15","delivery_date":"2026-09-17","eligible_qty":1000,"cash_per_share":"10","amount":"10000","evidence":"官方公告及前日持股核對來源"}
```

付款確認為 `kind=delivery, id=唯一付款編號, action_id=原權益編號, date=實際確認日, evidence=付款證據`。分割權益改用 `action_type=split, ratio=比例, result_qty=整數交付股數`。碎股、減資、配股或修正既有回報等複雜事件尚未支援，不得假設無事件直接繼續。

## 官方資料查核

[FinMind即時資料](https://finmind.github.io/tutor/TaiwanMarket/RealTime/)：Sponsor約10秒更新、`data_id=""`可單次全市場；`date`標為成交時間。文件沒有明確給出零股深度保證或買賣量單位，因此不能據此證明零股可成交。

[證交所交易制度](https://www.twse.com.tw/zh/products/system/trading.html)：盤中零股撮合9:10至13:30，零股單位1股；這與一般交易是不同交易管道。v2的盤中回報時段檢查依此制定，特殊交易狀況仍須另行核對。
