## 本次如何核對

新增的核對工具沒有匯入原回放引擎的現金、費用、資產或訊號計算函式。只重用官方零股回應的欄位解析器；普通盤價格、量與收盤估值取自封存行情。它依交易日重新建立股數、現金、待收權益及資產，再與舊報表比較：

- 1,380筆成交、1,403筆現金異動；沒有未解釋的入金或負現金。最低現金為25,651.24元。
- 49筆公司行動；股利由除息時的實際股數計算，付款後移除待收款；配股在交付前仍是待收權益，交付後才成為可賣股數，沒有重複計值。
- 4,820筆每日持股，全部重新查封存原始收盤價；1,867天的現金、持股市值、待收款及淨值相符。7筆沿用舊報價均為世紀已公告暫停交易期間，期末沒有沿用舊價。
- 248個已買進批次的進場條件，分別截斷在訊號日重算：前60日突破、量增、相對0050強度、市場趨勢及流動性條件；每批首次買入均為下一交易日。
- 4,367個三黑K判斷、183個觸發重新計算；對應成交均晚於訊號收盤。這不代表盤中事先知道當天收盤。
- 707份不同市場／日期的封存官方零股資料重新解析；上市、上櫃依當時的市場身分選擇來源，不能直接使用今天的市場別。

本次沒有重新下載整個市場的官方普通盤行情。官方歷史頁／端點未提供可讀取結果，專案既有TWSE存取暫停標記維持不變。因此原始普通盤仍依賴封存FinMind來源，不能把本次會計核對寫成完整外部市場資料認證。

原引擎先用浮點數計算日高低中點，再將該浮點數轉成Decimal算費用。接近整元或半分邊界時會產生差異。獨立工具改從原始高、低價的十進位字串直接算中點，找出：

**保持原1380筆成交股數不變**逐筆修正上述金額，期間累積現金差最多0.99元，期末差額恰為0元，期末資產及累積報酬不變。這是固定成交的金額覆核，不是假稱已用修正引擎重新決定每一天的委託股數。原封存研究及引擎未被覆寫；核對報告明確保留`strict_decimal_costs_match=false`，不把已知小錯誤藏成通過。

## 這個數字不能證明的事情

1. **可實現成交價**：買賣用次日各渠道`(最高+最低)/2`加設定滑價，不是次日開盤成交。這個中點要等全天結束才知道；本次證明訊號沒有取用未來價格，沒有證明真人可事先掛到這個價。
2. **可成交的股數與時間**：1%日量上限已重算，但日量不是委託簿深度或排隊順序。封存的未成交／分批成交仍只是模型。
3. **無偏的未來優勢**：歷史市場名單、修訂資料及完整公告時間並非全市場逐點完整認證；本次核對已買進批次，沒有另外證明所有歷史候選池均完整。這些年份也已反覆研究，並非未見資料。

因此本次狀態仍是`live_qualified=false`、`actual_fill_verified=false`、`unseen_validation=false`。能給的結論是「封存資料與既定模擬方式下，這個累積報酬有逐筆帳本支持」，不能給「你實際投入100萬元就能變成2615萬元」的保證。
