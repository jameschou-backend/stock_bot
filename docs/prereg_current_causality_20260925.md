本文件先於本次稽核結果固定檢查方法。不計算或比較報酬，不改策略、來源快照、實盤設定、排程或成交帳本。

## 來源與重建

- 使用 `.cache/five-axis-20260913/rebuild/` 的四個行情矩陣及 `signals.json`，公司名冊來自其 `identity.json` 指定的 `.cache/million-replay-signals/companies.parquet`。
- 驗證 rebuild manifest 的所有檔案、identity 的全部上游輸入，以及 `scripts/prepare_five_axis.py` 和其事前文件的 SHA256。記錄本稽核、重用 helper、測試、Python/numpy/pandas/scipy/pyarrow 版本及所有直接/identity 指定依賴雜湊。
- 按 `prepare_five_axis.py` 的既有規則，從原四個矩陣重做 price chronology quarantine，逐值核對重建後矩陣；不修改原準備程式或其輸出。
- 以既有 `build_signals` 完整重建，核對封存的完整輸出。只排除 `diffusion.stats.seconds` 執行耗時；接受、拒絕、分群、事件、趨勢及其他統計均須精確相同。接受訊號必須是 458 筆。

## 固定切點與比較

1. 保留 2026-09-12 舊文件的 19 個季度/期末要求日期；非交易日取之前最後交易日。
2. 加入訊號期間每個月第一個實際交易日、每個完整月份最後實際交易日，以及訊號期末。完整月份定義為矩陣可看到下一個月的交易日；未完月份不可假稱月末。切點合併去重，保留各類標記，不根據報酬或通過與否選日期。
3. 每個切點重用舊 helper 做兩種獨立轉換：刪除未來行情（僅保留下一交易日的全空白列供隔日委託標記）；未來既有價量按日期/股票交錯乘 8 或 0.125，原缺值保留。所有四個矩陣一同處理，切點當日以前必須逐值不變。
4. 比較截至切點的所有接受、拒絕候選欄位、0050 趨勢和該月以前的分群證據。舊 helper 明確排除分群的後續 `leader_rejections`；本次另按日期補回截至切點的拒絕紀錄。事件之後的確認結果及後續統計不屬當時可知決策，不列入截斷比較；它們仍列入完整重建比較。
5. JSON 欄位精確比較，不容忍數值差異；每個案例留下預期/實際摘要及各部分雜湊、實際切點、標記、下一交易日與耗時。任一不同即失敗，仍記錄其餘案例。

## 完成條件與邊界

預設最長 600 秒，在各重建步驟間檢查時間預算；未完成所有指定案例不能通過。來源缺少、雜湊不符、完整重建失敗、例外或時間不足，都寫明失敗並以非零狀態結束，不跳過或改用舊訊號。結果不得覆寫既有檔案；執行結束再次驗證所有來源/程式/本文件雜湊。禁止網路連線，嘗試連線亦視為失敗；無 FinMind 請求、模型訓練、DB 寫入或交易。
