# 新光金合併停牌的委託處理

`first_volume_bar_price` 的 2025/7/11 訊號產生下一交易日新光金買單，但 7/14 已進入合併停牌。原引擎在判斷停牌前，先要求當日有效漲跌停價，因此中止。帳戶當時沒有持有新光金。

[TWSE 2025/6/27 原始公告](https://www.twse.com.tw/staticFiles/news/news/tsecnews/8a8216d697769dcf0197b0ab734100e2.pdf) 已下載並核對第 1 頁：7/14 起停止買賣，7/24 終止上市。原始回應、取得計畫、時間、PDF 與擷取文字均保留雜湊；此為停牌前已公告的資料。

新入口 `scripts/research_all_entry_accounts_merger_halt.py` 沿用全部配股補件，增加 `--merger-halt docs/all_entry_2888_halt_20261012.json`。只對已證實停牌期間、未持有 2888 的買單建立零股數拒絕，保留原候選次序、預留預算與當日資源鎖定，不製造行情或漲跌停價，也不讓拒絕單資金改買下一檔。既有停牌資料機制提供明確不可成交的零活動紀錄。

若帳戶持有合併權益或嘗試賣出，仍會中止，必須另建普通股及特別股換股模型；不會把持股刪除或歸零。獨立發布核對拒絕任何停牌後 2888 正股庫存、成交或該拒絕單現金異動。所有已完成帳戶另確認沒有未建模的合併持股。

測試使用真正的混合整零股委託層，確認不讀取缺少的停牌日限制、預算保留、零成交，且未證實的停牌仍保留嚴格缺件錯誤。重跑須核對 2025/7/14 前 367 個交易日帳本完全相同。

舊帳戶若已因開盤名額鎖定而以零股數、零預算拒單，發布時獨立確認零持股、零成交、零現金異動後保留。不得要求這種既有拒單改成新版原因字串，更不能因此更動財務帳本；任何非零預留或未知拒絕原因仍拒絕發布。
