# 100萬元歷史交易帳本

這份報表將既有「族群領先股、趨勢通過才進場、3部位、63交易日」轉為新台幣現金及整數股份，期間2022-01-03至2026-09-09。本金100萬元，可買零股。期末保留股票、0050、現金及應收權利，沒有假設全部變現。

結果是扣掉逐筆佣金、交易稅、滑價之後的條件式模擬。選股名冊沿用舊研究，沒有完整納入歷史已下市公司；同段歷史曾用於研究選策略，不能當作未見資料或實盤證據。完整事前規格見 [固定規則](prereg_million_replay_20260910.md)。

## 如何查看

產出位置 `outputs/million_replay_20260910/一百萬歷史交易帳本.xlsx`。先看摘要的策略及0050同期比較，再按日期篩選全部買賣；每日資產列出現金、市值、應收及總資產，每日持倉可反查股數。交易表的當日期末資產是同日收盤結帳值，不是盤中撮合瞬間資產。

一張和不足一張分為兩筆委託及費用，因此同一天同股票可能有兩列。0050的買賣包括本金配置、股票買入前籌資、退出或領到股利後再投入。未成交表包含量不足、漲跌停、缺合法零股報價、滿倉或重疊事件；賣不掉的股份會繼續存在帳上。

## 成交能力

股票買入需前20個交易日完整資料，平均成交金額估計至少5,000萬元。估計金額為原始收盤價乘股數，並非交易所逐筆實際成交金額。

普通交易每股每日模擬成交量不超過前20日均量和當日量各1%；零股另外查該市場、該日期的官方盤中零股資料，上限為當日零股量5%。買進漲停、賣出跌停、單一成交價、無價量或無合法零股報價會拒絕；無漲跌幅限制的特殊日期也保守列不支援。

這些檢查降低小量股假成交問題，但日資料沒有完整委託簿，不能證明每一筆真實委託可照模擬價格成交。普通交易採日收盤、零股採自己的最後成交價，再各扣每邊0.45%滑價，帳上清楚分開參考價及滑價成本。

## 重現及效能

首次來源準備（需FinMind token及本機既有資料庫、原研究封存）：

```sh
make prepare-million-replay
```

首次完成會保存所用價量、股利、公司行動、零股及漲跌停來源，再禁止網路重跑兩個帳戶，逐項比對交易、現金、股數、每日NAV及公司行動。已封存的結果不允許同名覆寫。

後續完全離線重跑：

```sh
make research-million-replay
make verify-million-replay
```

Excel匯出使用本機Codex提供的Node及`@oai/artifact-tool`，不重新抓資料或執行策略：

```sh
node scripts/build_million_workbook.mjs
```

若依賴安裝於其他位置，可用`--runtime-modules /absolute/path/to/node_modules`指定。匯出器先確認報告封存及離線重現成功，再重算Excel公式並比對帳本，保存各工作表預覽。輸出及檢查檔不加入Git。

FinMind一律使用專案共用快取與全域配額器，6,000次／小時保留10%緩衝。HTTP402／配額不足時停止並保留已有來源，下次可續用，不另外開平行帳號或繞過限制。官方零股API與FinMind分開記次數。純帳本重算不重新抓全市場，也不重訓模型。

`.cache/million-replay/manifest.json` 封存輸入、程式、runtime、來源與输出SHA256；`report.json`包含完整明細，`summary.json`為摘要。原舊回測封存不變；本次另外修補新資料庫匯出缺少的市場日和0050價格，不能據此宣稱舊封存研究也缺同樣日期。

## 股利及股份

除息日先鎖定舊持股權利，付款前列應收不能買股。分割改股數；股票股利等新股交付才交易。0050使用精確4:1分割。4123以公司公告組成加總99.16825873股／千股，2023-10-13交付；集保帳簿劃撥的不足一股款作費用，淨入帳為0，其現金股利總額依公告捨去元以下。

帳戶不參與現金增資認購。股票權益條款或來源不完整時會停止計算，不能套還原價比例捏造可賣股數。[公司公告核對](million_replay_corporate_overrides_20260910.json)保留來源及頁次；事後年報僅驗證公司行動，不用來倒填選股訊號。個人所得稅與補充保費未計入。
