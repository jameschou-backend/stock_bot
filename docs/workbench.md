# 台股投資工作台

這一版把資料更新、候選觀察、交易計畫、成交記帳和回測放進同一個入口。畫面使用真實資料；沒有預填使用者本金，也沒有已驗證獲利的宣稱。現有模型仍屬研究策略，還原價、歷史可用時間及未見測試期尚待完整驗證。

## 啟動與操作

```sh
pip install -r requirements.txt
make workbench
# 另一個終端；MCP 透過此 API 讀資料
API_HOST=127.0.0.1 make api
```

工作台：<http://127.0.0.1:8502>。`make workbench` 先以可重跑 migration 建立三張 `workbench_*` 表，再啟動 Streamlit。保留側欄既有進階研究頁面。API 的 `/workbench/*` 只接受本機連線；這是個人工作台，沒有多人授權或遠端部署設定。

1. **今日觀察**：股價與訊號日期、上市／上櫃覆蓋、近 60 分鐘請求用量。展開「資料狀態與更新」啟動更新；更新股價明確選用 FinMind Sponsor 路徑。
2. **持倉與成交**：先輸入自己的期初現金。紙上練習與實際成交分開記錄；買賣輸入股數、成交價、實付手續費與交易稅。一次成交成功後需按「記錄下一筆成交」再繼續，避免連點重複入帳。
3. **交易計畫**：設定買價、警戒價、風險比例和部位比例。試算包含同檔既有持倉及未完成計畫占用、最低手續費、稅與 0.6% 來回滑價壓力；跳空損失仍可能超過估算。儲存計畫預留資金，部分成交後可取消剩餘數量。
4. **策略驗證**：選區間與持有檔數，開始背景回測；每 5 秒更新工作進度。快速模式減少模型樹數，必須與正式模式分開解讀。固定次一交易日進場、0.585% 來回成本外加 ATR 滑價模型，730 天滾動訓練窗。

工作台不送券商委託。成交帳本使用含買入費用的平均成本，賣出時再扣實付費稅；未實現損益依顯示的收盤報價估值，不含未來賣出費用。缺報價顯示未知，不當成零損益。目前不支援融資融券、股利／分割事件、後續入出金或回插早於最後一筆的成交。

## 效能與額度

- Sponsor 固定硬上限 6,000 次／小時，預設只使用 5,400 次、保留 600 次。本機 API、CLI、畫面、MCP、重試共用持久化 SQLite 帳本，重啟不歸零。其他裝置與官方網頁的使用量不可見；供應商 402/429 會讓所有本機請求暫停。詳見 [FinMind 效能說明](finmind-performance.md)。
- 日價／還原價／PER 依官方支援按日全市場取得；月營收按月份取，不用不受支援的逗號 `data_id`。最近七天上市或上櫃資料有缺口時重抓，不以全表最新日期判定完整。
- 成功的相同 API 查詢短期快取；同時請求合併，HTTP Session 重用。沒有變動的日期跳過 ingest。資料不足不以另一種來源或虛構資料填補。
- 特徵計算先排除非四碼代號，避免歷史權證混入數萬個滾動計算。近期缺行情補齊後，對照股價覆蓋率重算缺漏特徵。
- 回測讀取價格時只檢查價格快取，日期範圍以 DuckDB 下推；相同 X/y、權重、群組、參數與版本的模型重用訓練。首次缺快取或修正歷史資料仍需要重建。
- 工作台同時只啟動一個研究或資料更新工作；重複點擊回傳同一工作。CLI `run_daily.py` 與 `run_backtest.py` 也共用檔案鎖；其他歷史研究腳本尚未全部加上排他鎖，勿同時執行。背景工作最長 30 分鐘，超時回報失敗。

2026-09-09 本機驗收結果（會受資料量、CPU 與快取狀態影響）：

| 範圍 | 實測 |
| --- | --- |
| 同一 226 天特徵計算段 | 36,544 個代號／約 94 秒 → 2,421 個四碼代號／約 7 秒 |
| 已更新狀態重跑完整 `make pipeline` | 18.704 秒，成功；未重新計算整段特徵 |
| 三個月快速回測，含成本／滑價 | 11.857 秒；相同指令重跑 11.559 秒，權益曲線與報酬指標一致 |
| 回測實際可用區間 | 2026-05-12～2026-08-10，4 個持有期間；不是今天以前所有交易都已成熟 |
| 工作台資料狀態 API | 約 0.17 秒；候選名單約 0.01 秒 |

這些是執行效率與可重現性驗收，不是投資有效性的證明。上述回測仍採 `raw_close`；畫面基準是引擎股票池等權報酬，不能當成台灣加權報酬指數。資料歷史修正後應重新驗證快照；舊快取的日期與列數相同不代表內容沒有變動。四碼也不等於所有代號都是普通股，候選名單另以股票類型篩選。

## MCP 與專案 Skills

使用一個 **stock-bot MCP**，讓 FinMind 查詢與工作台走同一額度入口。沒有另外啟用會繞過本機額度帳本的官方 FinMind MCP。

```sh
make mcp-install
codex mcp add stock-bot -- "$PWD/.cache/mcp-venv/bin/python" "$PWD/scripts/stock_bot_mcp.py"
```

MCP Python 環境獨立在 `.cache/mcp-venv`，SDK 固定 `mcp==1.30.0`。本次本機已完成安裝與設定；Codex 若尚未顯示新工具，重新載入專案／工作階段。API 須持續啟動在本機 8000 埠。伺服器不持有 FinMind Token，不寫帳本，也不能執行任意命令。

| 工具 | 用途 |
| --- | --- |
| `get_data_status` | 資料新鮮度、市場覆蓋及額度 |
| `get_candidates` | 候選股票、分數、訊號與報價日期 |
| `get_portfolio` | 紙上／實際帳本持倉與含費損益 |
| `get_trade_plans` | 計畫與部分成交狀態 |
| `get_strategy_evidence` | 驗證限制、既有研究及背景工作 |
| `get_trade_review` | 成交與交易費用檢視 |
| `query_finmind` | 經共享額度與快取查單股資料；最多 31 天、分鐘 K 限一天 |

`.agents/skills` 中有四個專案技能：`stock-data-audit`、`stock-strategy-research`、`stock-daily-plan`、`stock-trade-review`。各自要求先查資料與驗證狀態，不把排序當上漲機率，不把 UI 初值當成使用者設定，也不宣稱已驗證獲利。

資料與備份：成交和計畫存在 MySQL；應納入既有 DB 備份。研究工作、報告和日誌在 `.cache/workbench/jobs`，模型在 `.cache/training`；清理前先下載要保留的研究摘要。FinMind 帳本預設在 `~/.cache/stock-bot/finmind.sqlite3`，不可刪除以重設額度。所有秘密仍由本機環境提供；`.env` 未修改。

官方參考：[FinMind 技術資料](https://finmind.github.io/tutor/TaiwanMarket/Technical/)、[FinMind MCP](https://finmind.github.io/tutor/ai/Mcp/)、[MCP Python SDK 1.30.0](https://pypi.org/project/mcp/1.30.0/)。
