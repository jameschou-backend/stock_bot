# 永豐金大戶投回報核對

已確認使用者採大戶投APP手動下單。沒有啟用Shioaji、串接帳戶、操作APP或下單。官方手冊提供委託與成交回報、刪單操作；目前尚未取得使用者實際匯出檔，未聲稱支援原生CSV自動解析。

畫面入口：策略驗證 →「大戶投：賣出／撤單後可以補位嗎？」。依範本整理單日事前計畫及回報後上傳；核對結果可下載，不更改紙上／真實帳戶。

1. 保存前一交易日的候選、固定限價、含費預算與股數，另列期初庫存、可用現金及未交付股票權利。範本的金額均為新台幣分、股數為股，不是張。
2. 從APP記錄每筆委託、部分成交、刪單請求、刪單成功或失敗。成交價、費、稅分欄；收盤日結單若只有總量而無時間，不足以證明盤中補位順序。
3. 保存事件發生與收到回報的時間，包含+08:00時區；決策不能早於收到所依賴回報。時間精度不足而相同時戳者先保留為未證明，不猜順序。
4. 撤單成功須核對累計成交股數與取消剩餘股數，兩者不合不釋放名額。成交晚到必須先重建該段，不在取消後直接補登並沿用後續買單。
5. 完成賣出或撤單後，另取**已扣其他未成交預留的可用買進額度**快照，填covers_through所涵蓋的最後事件。不能拿交割帳戶存款、交割款、可出金額或額度上限直接代替。快照金額不得超過本策略帳本可用現金；若帳戶混有其他交易，先獨立對帳。

支援事件：funds_snapshot、submit、fill、cancel_request、cancel_ack、cancel_rejected。沒有ack不視為取消；剩股或未交付權利照占股票名額；整張／零股共享名額。部分成交保留未用預算，新的可用額度須有獨立快照。盤終過期／公司行動／外部存提款須先另行核對，本版不推定其效果。買進額度不等於保證券商接單。

每筆需source_sha256對應自行保存的原始回報／截圖檔，勿含姓名、帳號、身分證字號等個資。雜湊僅識別提供的證據，不能認證真實性；手動紀錄即使全部一致仍是user_transcribed_not_broker_authenticated，live_qualified=false。

空白或虛構範本不是實際成交證據。使用者提供真實紀錄前，券商執行驗證仍未完成；不應為了測試而特地下單。帳號密碼、憑證與驗證碼均不需要提供。

範本的example_only=true會刻意拒絕通過；完整替換為實際回報、時間、股數、證據雜湊後才移除此旗標。若有成交，以fill事件列qty、price_cents、fee_cents、tax_cents；撤單失敗改列cancel_rejected與對應request_id，不能沿用cancel_ack。原生APP能否匯出上述全部時序欄位仍待實檔確認；沒有欄位就保持缺件。
