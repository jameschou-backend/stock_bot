## 資料可信度：找到具體缺口，尚不能標記全部修復

5次全市場日期抽樣出現239、235、251、271、321個不在封存名冊的代碼；其中大多為興櫃範圍差異。以供應商現有市場標籤分類，屬上市或上櫃的分別為50、36、27、18、11個。這些現有標籤不能取代歷史市場身分。

期間內50筆下市紀錄全部不在封存名冊。DB均有下市前價格，但50檔上市日期全缺，22檔有下市後行情；還看到以匯入觀察日期記為listed的歷史列。例如2456的DB含2026/6/17收盤110.5元與成交量，FinMind同日即時查詢卻為空。這是待查資料衝突；未直接刪除或按目前代碼資訊回填歷史。

兩份保存的還原價版本比較，458次候選的20日報酬沒有超過0.1個百分點的差異；整個矩陣仍有5,695個可比較位置超過門檻。相同資料血緣的版本一致不算獨立官方驗證。現金策略未使用營收、財報，因此這些公告時間不屬於本版訊號輸入；歷史價格與股票母體問題仍適用。

## 效能、驗收與重現

29個完整帳戶離線重播約73.2秒、0次FinMind呼叫。研究準備的有界計數為FinMind 7次呼叫與交易所 142次HTTP嘗試，含失敗；另外的資料盤點、公司行動刷新、TLS診斷與pipeline驗收分開計數。所有FinMind呼叫仍走共享限流，不重訓模型。

完整測試2,354 passed、57.33秒，包含20項新增測試。明確使用FinMind的pipeline成功；官方來源在指定驗證過的憑證鏈後仍遇傳輸截斷，因此沒有宣稱預設官方pipeline已正常。make api啟動後，health、picks、models、jobs四端點curl均200且JSON可解析。

舊封存app/finmind.py與現行版本有已知差異；本輪明確建立新研究來源並記錄舊新hash，其他父來源hash皆相符，且中性現金帳戶逐欄重現。沒有修改舊manifest掩蓋差異。

```sh
python scripts/prepare_tpex_tls_chain.py --output .cache/tpex-tls-new
python scripts/research_cash_risk.py --offline-replay
```

第一次建立新的研究輸出，才能使用 `--output <新目錄> --prepare`；缺股利快取會明確阻擋，需要在獨立inputs/dividends補齊經驗證的來源後再續跑，不能修改父研究。TLS鏈使用 `REQUESTS_CA_BUNDLE="$PWD/.cache/tpex-tls-new/bundle.pem"` 明確指定給當次prepare程序。

工作台「策略驗證」新增「現金版補強」表格，可切換成交壓力、整戶減碼與資金路徑，不會因開頁重抓資料或重跑研究。
