## 跨日串接內容

- **重新規劃與複利：** 每天以實際前日NAV作每檔預算上限，按成交金額、股票代號與事件ID固定排序；不是每天重設100萬元。只有確認可用現金及實際成交後的名額能供買單使用。預估賣款只用T日已知價格作計畫，不能代替實際資金確認。
- **出場延續：** 12%條件看前一日還原收盤相對實際進場當日還原收盤；63日從實際進場交易日開始計。觸發後即使價格反彈，尚未賣完的餘股仍保留原出場原因與訊號日，隔日重新依合法限價送出。當日不反向重買同股，避免同一盤別成交量被多張買賣單重複使用。
- **權益與交付：** 現金股利先記應收，股票股利先記未交付股數；可用日才轉現金或股票。未交付股票繼續占同一檔名額，不能先賣完原持股就算名額全空。分割／減資依明確換股比例及返還金額轉換，零碎權益需明確現金清償價格。
- **待用賣款：** 未在當日回用的賣款先保留應收，依本研究保守假設在T+3交易日開盤前轉可用，不假裝知道個別券商的盤中額度。未到期款不能買進，但應收價值仍包含在NAV。
- **缺件回復：** 行情缺盤別、公司行動缺公告／交付依據、收盤估值缺漏時，當天全部回復到前一日狀態，保留待查的事前計畫。不將缺資料改成零成交或零價格。

## 取得資料後如何繼續

目前最小補件是2022/1/4上市富鼎8261、上櫃佳邦6284，及2022/1/3上市0050的零股撮合。補完這三個股票日後才能知道後續回放實際需要哪些日期；不能把它們當成全期間只差三天資料。

```bash
# 精確重現本輪第一個缺件位置，0次行情請求
python scripts/research_contingent_portfolio.py --verify

# 有新來源後，以新目錄啟動，保留原紀錄
python scripts/research_contingent_portfolio.py \
  --inputs .cache/crossday-new-inputs/manifest.json \
  --output .cache/crossday-with-new-sources \
  --publish artifacts/forward_simulation/crossday-with-new-sources.json
```

額外來源manifest有`actions`和`tapes`兩個陣列。`tapes`每項需有`date`、`stock_id`、`market`、`channel`、`format`、`path`及`sha256`，格式沿用[逐筆串接文件](research_contingent_replay_20260914.md)的規格化JSON；FinMind整張原始檔另要`metadata_sha256`。不會只因副檔名或檔案放進資料夾就自動視為可信零股資料。

`actions`需有唯一`action_id`、`stock_id`、`date`、`known_date`、`source_id`、`verified`、`available_date`、`reference_cents`及各類型條件。現金股利使用`cash_per_share_cents`；配股用`new_shares_per_share`；分割／減資用`exchange_ratio`，減資另要`cash_return_per_old_share_cents`。有零碎股份則必須有`fractional_cash_per_share_cents`。股票與現金不同日交付時應分列相同除權日、不同權益與可用日的事件。既有未交付股票權益再遇換股，沒有完整轉換條件就停止。

原公司行動來源若只知道除權息日，卻沒有公告可用日、交付與轉換依據，不會自動標為verified；程式可處理規格化的已確認條件，不代表真實歷史公司行動證據已全部補齊。來源宣告也不等於獨立稽核，兩個帳戶仍為`live_qualified=false`。
