# POC硬篩＋紅K原版：訊號準備與手動成交回報

使用者已選定「只要準備訊號；買進時會再告知，屆時才記錄」。因此目前範圍只有訊號準備與封存。尚未回報的交易不可建立委託、持倉或成交；未來至少依買進日期、股票、股數及成交價辨識，費用不明就標示待補，不可當成零費用。同一筆回報須先查重。成交來源與自動模擬帳戶不是現在準備訊號的前置條件。

本次選定 `poc_up_red`。這是觀察準備版本，尚未建立資金帳戶或啟用成交；既有其他策略的紙上帳戶保留不動。

## 已補齊

- 凍結原版規則、程式指紋與8份已完成對照來源：原版及同成本0050各4種成本，不重跑歷史帳戶。
- 準備本金100萬元、3個活躍名額、閒置現金；金額僅為設定，不是入金紀錄。
- 每日全部符合訊號按當日20日平均成交值由大到小、同值按代碼排序；保留持續符合者，不能套用畫面的首次訊號篩選或顯示順序。
- T+1進場；沿用官方預先可知漲跌停限價、12%收盤停損、63交易日期限、進場後三黑出場及原版殘餘零股政策。
- 新建獨立、雜湊串接的觀察帳本。相同內容重送不重複；已封存的合格日不能覆寫。資料不足或過期會記為阻擋觀察，不算成無訊號日或事前委託。

## 每日封存方式

先完成當日行情、POC及掃描的增量發布，沿用既有 shared FinMind quota gateway 與快取。此工具不抓資料、不執行回測，不會以昨天結果冒充今天。

當日台北時間18:00後、下一交易日前，使用該日新發布且已封存的 audit 路徑與 SHA：

```sh
python scripts/prepare_poc_paper.py capture \
  --audit <當日掃描audit路徑> --audit-sha <當日audit的SHA256> \
  --output <新的準備報告路徑>
python scripts/prepare_poc_paper.py status
```

必須有資料庫交易日曆提供下一個交易日；不能猜週一至週五。`status` 為唯讀，不會建立空帳戶。原版規則或程式變動時需註冊新版本並保留舊紀錄，不能改寫已凍結版本。本次沒有新增自動排程。

## 若日後改做自動模擬成交，仍缺的接線

1. **成交來源**：券商模擬帳戶的委託／成交回報，或可識別普通盤、盤中零股通路的時序資料。FinMind既有檢查未取得足夠零股時序，日彙總或報價不能轉成已成交。
2. **POC專用帳戶與執行轉接**：既有leader帳戶有閒置0050與不同出場規則，不可直接借用。接入後需驗證預掛單、現金預留、3名額、部分成交、殘餘零股、隔日賣出重試、費稅、公司行動與每日對帳。成交來源尚未確定，因此本版不產生資金與成交紀錄。
3. **當日可用資料**：未知原因、價格調整、當時證券身分及交易限制要保留，不能把衝突改成通過。10/14已完成掃描可以作準備核對，但10/15才封存的10/14訊號不能回填成事前紀錄。

成交來源確認時需取得的資料契約：

| 類型 | 必需資訊 |
|---|---|
| 委託 | 策略版本、訊號雜湊、唯一委託ID、證券代碼、買賣方向、整股／零股、股數、限價、送單與有效截止時間、時區 |
| 回報 | 來源、原始回報指紋、唯一成交ID、對應委託ID、成交時間、價格、股數、佣金、交易稅；取消／拒絕及未成交餘量 |
| 行情模擬 | 資料可用時間、交易通路、量的單位、序號與時序完整性；成交規則須在觀察期開始前凍結 |
| 對帳 | 現金、費稅、持倉與零股、未成交單、公司行動、應收款、已實現／未實現損益 |

券商的模擬成交也需標為模擬，不會自動變成真實成交證據。每日高低價、HL2、零股日彙總及看到的報價皆不是成交回報。
