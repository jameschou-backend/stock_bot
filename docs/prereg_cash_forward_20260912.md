# 前向模擬現金版：取消閒置0050配置

使用者於2026-09-12要求先拿掉閒置資金買0050。本版只修改策略帳戶的閒置資金去處：保留現金、不計息；0050獨立比較帳本仍買入持有並再投入已交付股息。

## 版本與初始計畫

- 新目錄`.cache/forward-simulation/cash-v1/`；原始前向帳本與`.cache/forward-simulation/v1/`不覆寫、不移除事件。
- 初始化只允許在原共同進場日開盤前，且來源未有成交／權益／交付。承接相同9/11收盤、100萬元本金與9/14個股計畫，另加現金配置協議及核心程式SHA256。
- 在新策略帳本追加取消原未成交的0050買單；個股委託保留。新基準帳本的0050買單保留。這是事前變更配置，不是賣出已持有0050。
- 基礎會計與撮合協議仍由原凍結程式驗證；新增cash_allocation_protocol明確覆蓋閒置資金政策並再次驗證。策略出現0050有效委託、0050持股或協議之後的新0050委託即拒絕執行。
- 舊v1保留為歷史對照紀錄，現有排程改用現金版，不同時跑兩份策略。

## 沿用規則

選股仍用同一個leader_now與訊號日趨勢ON門檻、次交易日委託；最多三個個股部位、前一收盤淨值三分之一預算、相同流動性、12%收盤停損與63交易日出場。沒有把每檔部位放大來花掉現金，也沒有加碼。

所有個股提案沿用原計算，只過濾0050配置相關命令。個股資金需求仍可保留，並只在真正模擬入帳資金足夠時釋放；因此保留現金移除了「必須先賣0050」的依賴，不代表排隊、流動性或所有個股間資金依賴消失。

沿用每15分鐘兩次快照、10%深度與10%成交量增量上限、0.1%不利滑價、手續費與交易稅、休市跳過、不補推未觀察成交，以及持股公司行動人工核對。兩份比較帳本各自100萬元，模擬結果不視為券商成交。

## 舊回測的參考與限制

2022/1/3至2026/9/9歷史日資料帳戶：原閒置0050版費後+710.81%、年化56.37%、最大回撤-35.89%；現金版+541.90%、年化48.76%、最大回撤-25.52%；0050比較+242.07%。詳見[既有配置研究](research_cash_allocation_20260910.md)。

這是已做過的歷史對照，不是本次新回測。原研究採日終成交模型及每邊0.45%滑價，和現前向撮合不同；不把+541.90%當作新版已驗證報酬。舊研究的盤中成交、歷史資料時點、存活者與反覆研究限制仍存在。

## 操作與排程

```sh
python scripts/run_cash_forward.py init
INGEST_PRICES_SOURCE=finmind python scripts/run_cash_forward.py run --observe-seconds 20
python scripts/run_cash_forward.py status
```

工作台「策略驗證 → 前向模擬版本」預設現金版；顯示現金、預留及個股計畫。舊版可切換查看，切換畫面不會更換排程。

更新原Codex heartbeat的執行命令與讀取目錄，保留頻率、同一對話與有意義變化才通知的意圖。本機需保持電腦、Codex、MySQL及網路可用，見[官方排程文件](https://learn.chatgpt.com/docs/automations?surface=app)。每日pipeline、增量訊號與MIS快取共用既有機制，不新增全市場逐股抓取。

股價資料來源在命令中明確指定FinMind，沿用共用快取與限流。2026-09-12預設官方來源因TPEx TLS憑證驗證失敗；沒有修改`.env`、關閉憑證驗證或加入自動退回來源。明確指定FinMind後，完整pipeline連續兩次成功；這不代表官方來源的TLS問題已修復。
