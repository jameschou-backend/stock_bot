# 0050前向比較與獨立出場檢查（2026-09-12）

## 本輪結果

補上與策略同樣100萬元起點的0050紙上比較帳本。另確認並修正一個流程漏洞：舊 `forward_portfolio_service.proposals()` 在檢查持股出場前就要求今日選股訊號；缺訊號會阻擋停損計畫。

新增 `forward_comparison.save_exits()` 獨立檢查出場、用交易提交保存，再處理新買單。訊號缺失、來源錯誤或買單驗證失敗只記錄 `entry_gap`，不回滾已保存的出場。出場仍需要當日持倉估價與公司行動核對；若缺少必要價格，必須明示缺口，不能推論為繼續持有。

不是新的選股回測，不提高歷史報酬，不宣稱已通過實戰驗證。

## 版本與時序

- 保留 `app/forward_portfolio.py`、`app/forward_portfolio_service.py`、`app/forward_journal.py` 原始程式及封存雜湊。
- 使用同一會計引擎；新增 `execution_protocol` 事件明列執行流程版本、帳本角色和新模組SHA。原事件不覆寫。
- 策略帳本維持 `.cache/forward-validation/portfolio-v2.sqlite3`；基準另存 `.cache/forward-validation/benchmark-0050.sqlite3`。
- 基準可以在共同進場開盤前引用策略已封存的初始收盤；事件以**實際建立時間**寫入，另記原始收盤日期及雜湊，不倒填觀測時間。
- 若共同進場已開盤，或策略已有成交／公司行動，拒絕倒建基準；已存在的相同基準可重讀，不重新開始計算。
- 既有舊CLI入口仍保留；更新後 `portfolio_forward.py plan` 與工作台使用獨立出場流程。直接呼叫舊研究服務不等於新流程。

## 預先固定的比較規則

| 項目 | 策略 | 0050基準 |
|---|---|---|
| 期初本金 | 100萬元 | 100萬元 |
| 首次可交易日 | 原策略第一個已封存買單日 | 相同 |
| 初始0050參考價 | 原封存收盤價 | 引用同一筆來源 |
| 成交證據 | 紙上回報，非券商認證 | 獨立紙上回報，非券商認證 |
| 成本 | 成交價、實際登錄費稅 | 同會計引擎、獨立登錄費稅 |
| 未成交 | 保留原始計畫、核對後取消剩餘 | 同樣保留；初始未成交本金不在次日自動重買 |
| 股息 | 應收與交付分開，交付後才可用 | 僅已交付股息提出次交易日再投入計畫 |
| 股息再投入預算 | 依策略既有資金流程 | 已交付股息減去已投入含費金額及未成交預留；不能挪用初始未成交本金 |
| 0050賣出 | 依原策略資金需求 | 買入持有、不換股、不套用個股停損 |

基準是「實際有紙上成交證據的0050帳戶」，含未成交現金與費用，**不等於0050單純價格漲幅**。股息再投入有整數股數與最低費用限制，零頭留現金。再投入提案不保證成交。

## 何時可以顯示比較

兩帳本須符合：同一起始收盤雜湊；各有成交回報；最近估值同日；共同期間每日收盤結算齊全；NAV非未知；0050價格相同（數字格式不同不算差異）；交易日曆一致；基準委託只含0050初始買入或股息再投入。

不符時只顯示原因，不以0報酬填補缺口。符合後顯示累積帳戶報酬、資產曲線與領先／落後的百分點。所有畫面仍標記為使用者提供的紙上證據，`live_qualified=false`。少數交易或單段歷史領先不代表穩定優勢。

## 操作

研究頁新增「策略帳本／0050比較帳本」切換；兩份表單狀態隔離，避免將另一帳本的成交資料誤帶入。登錄、取消、公司行動與下載操作只作用於當前選定帳本。

```sh
# 在共同首次進場開盤前，建立獨立基準
python scripts/portfolio_forward.py benchmark-init
# 出場先保存，再嘗試新買入
python scripts/portfolio_forward.py plan
# 基準收盤：需先核對成交與公司行動
python scripts/portfolio_forward.py close --journal .cache/forward-validation/benchmark-0050.sqlite3 --actions-reviewed
# 已交付股息的再投入提案
python scripts/portfolio_forward.py benchmark-reinvest
# 對齊兩帳本證據後比較
python scripts/portfolio_forward.py compare
```

基準回報可用 `record --journal .cache/forward-validation/benchmark-0050.sqlite3 --report /absolute/path/report.json`，JSON欄位與原帳本相同。沒有排程、沒有券商下單、沒有自動把報價變成交。
