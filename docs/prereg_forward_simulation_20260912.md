# 自動前向模擬：事前固定規則（2026-09-12）

本實驗承接2026-09-11已封存、預計9/14進場的策略與0050計畫，各100萬元。選股、12%收盤停損、63交易日出場及NAV複利配置沿用原規則；本次只建立固定的觀察／撮合與每日執行流程。原始兩份帳本不接收模擬成交。

## 撮合假設

- 市場與交易別：上市／上櫃普通四碼股票及0050。MIS一般交易量由「張」換算1000股；盤中零股直接用「股」。不使用最後成交價替代對手盤。
- 觀察：同市場、股票、交易別的兩次快照，揭示時間間隔15至90秒；最新快照不超過15秒，委託至少提前15秒存在。盤中零股自09:10開始，整張自09:00開始，13:30起不推定撮合。
- 參與量：取兩次限價內可見深度較小值的10%，再與兩次觀察之間累計成交量增量的10%取較小值。依整張1000股、零股1股取整；可部分成交。沒有增量、資料錯誤、觀察中斷或無對手盤，均不成交。
- 價格：取兩次限價內五檔中的最不利價，再加0.1%不利滑價，按交易升降單位向不利方向取整；超出原限價即不成交。這是刻意保守的情境假設，並非撮合機制的精確複製。
- 成本假設：每筆模擬成交手續費0.1425%、最低20元；股票賣出稅0.3%、0050賣出稅0.1%；沒有折扣或當沖優惠。零股分批成交可能增加最低費用，現金不夠時不入帳。
- 同一帳本同一觀察的容量不可重用；兩次使用相同揭示時間不重複撮合。策略與0050是相互獨立的反事實情境，各自使用相同市場容量設定，不把兩份比較帳當作同時真實下單。
- 缺口：排程未執行、休眠或無有效報價的區間不補造成交；13:30後取消剩餘模擬委託並保留原因。賣出模擬入帳後才可釋放既有的盤前資金需求。

## 每日流程

排程每15分鐘喚醒本對話的有界程式，程式依台北時間及資料庫明確交易日曆判定階段：

1. 08:45至09:00：封存盤前計畫快照。
2. 09:00至13:30：先核對已知公司行動來源；取得一輪行情，等待20秒，再取得一輪。每輪最多12組市場／股票／交易別，不掃全市場逐股即時行情。零股時段由撮合器另行限制。
3. 13:30後：取消本日未成交餘量。
4. 18:00至20:00：每日pipeline成功一次後不重跑；封存增量訊號；公司行動來源更新、結算、建立下一交易日計畫及輸出報告。失敗階段至少15分鐘後再試，不清快取。

排程的pipeline明確設定`SPONSOR_INGEST=off`，省略目前未用於本策略的重型逐股Sponsor因子；不修改`.env`。所有FinMind請求仍經專案共用快取／配額。MIS快照獨立節流，15秒快取。訊號產生使用前一日封存矩陣作增量基底，排除供日曆用的未來空白列；保留原歷史名冊與各日來源，不重新訓練ML模型。

公司行動來源不代表完整公告覆蓋：**有持股的每日結算仍須使用者核對公告**，在畫面保存核對人與說明；核對綁定當日來源內容，來源變更或換日失效。漏登權益、碎股、減資等問題不能靠勾選確認繞過。排程只記錄阻擋原因，不自動聲稱已核對。

## 證據與評估

- 模擬帳本：`.cache/forward-simulation/v1/strategy.sqlite3`、`benchmark.sqlite3`。
- 模擬訊號帳本：同目錄`signals.sqlite3`，繼承已觀察的起點，後續與原始帳分開封存。
- 來源：`.cache/forward-simulation/market-quotes.sqlite3`保存原始MIS回應、來源時間及解析器雜湊。
- 每日執行狀態：`runs.sqlite3`；報告保留在`reports/YYYY-MM-DD/`，`latest-report.json`供畫面讀取。
- 模擬協議鎖定核心檔案SHA256；變更規則或執行程式會停止舊帳本，不能沿用舊績效。原始訊號與會計引擎檔案不修改。
- 追蹤扣費收益、相對0050差距、成交／未成交原因、觀察缺口。沒有完整共同每日結算，不顯示合格比較；即使可比較也永遠標成模擬。

只有兩次快照仍不能重建真實排隊、撤單與撮合順序。10%深度、10%量與0.1%滑價是固定假設；不稱為實際成交證據，也不證明能實戰獲利。沒有歷史或未來模擬結果作為本次參數選擇依據。
